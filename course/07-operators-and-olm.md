# Module 07: Operators & OLM (Operator Lifecycle Manager)

## Goals

- Understand Operator pattern and OLM components
- Install Operators from OperatorHub
- Manage Operator subscriptions and channels
- Create Custom Resources (CRs) managed by Operators
- Upgrade and uninstall Operators safely
- Troubleshoot stuck CSV (ClusterServiceVersion) and failed installs

## Key Terms

- **Operator**: Kubernetes controller automating app deployment/management
- **OLM (Operator Lifecycle Manager)**: Manages Operator lifecycle (install, upgrade, dependencies)
- **CatalogSource**: Repository of Operator bundles (RedHat, Community, Certified)
- **Subscription**: Declares intent to install/upgrade Operator from channel
- **CSV (ClusterServiceVersion)**: Metadata defining Operator version, permissions, CRDs
- **InstallPlan**: Generated by Subscription; executes Operator install/upgrade
- **OperatorGroup**: Defines namespaces Operator watches (AllNamespaces, SingleNamespace, etc.)
- **CRD (CustomResourceDefinition)**: Extends Kubernetes API with custom types
- **CR (Custom Resource)**: Instance of CRD managed by Operator

## Commands First

```bash
# List available CatalogSources
oc get catalogsources -n openshift-marketplace
oc get packagemanifests | grep -i postgres  # Search available Operators

# View Operator details
oc describe packagemanifest postgresql-operator -n openshift-marketplace

# Create OperatorGroup (required for namespace-scoped Operators)
cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: demo-operators
  namespace: ${NS}
spec:
  targetNamespaces:
  - ${NS}
EOF

# Create Subscription (installs Operator)
cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: postgresql-operator
  namespace: ${NS}
spec:
  channel: stable
  name: postgresql-operator
  source: certified-operators
  sourceNamespace: openshift-marketplace
  installPlanApproval: Automatic
EOF

# Check Operator installation progress
oc get subscription postgresql-operator -n ${NS} -w
oc get installplan -n ${NS}
oc get csv -n ${NS}  # ClusterServiceVersion

# Wait for CSV to reach "Succeeded" phase
oc get csv -n ${NS} -o jsonpath='{.items[0].status.phase}'

# List CRDs installed by Operator
oc get crd | grep postgresql

# Create Custom Resource (CR) managed by Operator
cat <<EOF | oc apply -f -
apiVersion: postgres-operator.crunchydata.com/v1beta1
kind: PostgresCluster
metadata:
  name: my-postgres
  namespace: ${NS}
spec:
  postgresVersion: 15
  instances:
  - replicas: 2
    dataVolumeClaimSpec:
      accessModes:
      - ReadWriteOnce
      resources:
        requests:
          storage: 10Gi
  backups:
    pgbackrest:
      repos:
      - name: repo1
        volume:
          volumeClaimSpec:
            accessModes:
            - ReadWriteOnce
            resources:
              requests:
                storage: 5Gi
EOF

# Monitor CR status
oc get postgrescluster my-postgres -n ${NS} -w
oc describe postgrescluster my-postgres -n ${NS}

# Upgrade Operator (change channel or approval)
oc patch subscription postgresql-operator -n ${NS} \
  --type=merge \
  -p '{"spec":{"channel":"stable-v5"}}'

# Manual approval for upgrades (safer for prod)
oc patch subscription postgresql-operator -n ${NS} \
  --type=merge \
  -p '{"spec":{"installPlanApproval":"Manual"}}'

# Approve pending InstallPlan
INSTALL_PLAN=$(oc get installplan -n ${NS} -o jsonpath='{.items[?(@.spec.approved==false)].metadata.name}')
oc patch installplan ${INSTALL_PLAN} -n ${NS} \
  --type=merge \
  -p '{"spec":{"approved":true}}'

# Uninstall Operator (delete CR first, then Subscription/CSV)
oc delete postgrescluster my-postgres -n ${NS}
oc delete subscription postgresql-operator -n ${NS}
oc delete csv <csv-name> -n ${NS}
oc delete crd postgresclusters.postgres-operator.crunchydata.com  # Optional

# View Operator logs
oc get pods -n ${NS} -l app=postgresql-operator
oc logs -f <operator-pod-name> -n ${NS}
```

**Why/Notes**: OLM automates Operator lifecycle, reducing manual YAML management. Operators provide day-2 operations (backup, upgrade, failover). Subscriptions enable automatic or manual upgrades. Always delete CRs before uninstalling Operators to avoid orphaned resources.

## Verify

```bash
# Check Operator installed

# Verify CRDs registered
```

## Mini-Lab (5-10 min)

**Scenario**: Install cert-manager Operator, create Certificate CR, upgrade to new channel.

1. **Create namespace and OperatorGroup**:

```bash
oc new-project demo-olm

cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: demo-olm-og
  namespace: demo-olm
spec:
  targetNamespaces:
  - demo-olm
EOF
```

2. **Install cert-manager Operator**:

```bash
# Find Operator
oc get packagemanifests | grep cert-manager

# Create Subscription
cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: cert-manager
  namespace: demo-olm
spec:
  channel: stable
  name: cert-manager
  source: community-operators
  sourceNamespace: openshift-marketplace
  installPlanApproval: Automatic
EOF

# Monitor installation
oc get subscription cert-manager -n demo-olm -w
oc get csv -n demo-olm
oc get installplan -n demo-olm
```

Wait for CSV to reach "Succeeded" (may take 1-2 minutes).

3. **Create self-signed Issuer and Certificate**:

```bash
cat <<EOF | oc apply -f -
apiVersion: cert-manager.io/v1
kind: Issuer
metadata:
  name: selfsigned-issuer
  namespace: demo-olm
spec:
  selfSigned: {}
---
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: my-cert
  namespace: demo-olm
spec:
  secretName: my-cert-tls
  issuerRef:
    name: selfsigned-issuer
  dnsNames:
  - example.com
  - www.example.com
EOF

# Verify cert created
oc get certificate -n demo-olm
oc get secret my-cert-tls -n demo-olm
oc get secret my-cert-tls -n demo-olm -o jsonpath='{.data.tls\.crt}' | base64 -d | openssl x509 -text -noout | grep Subject
```

Expected: Secret `my-cert-tls` contains self-signed certificate.

4. **Simulate upgrade** (change to manual approval):

```bash
oc patch subscription cert-manager -n demo-olm \
  --type=merge \
  -p '{"spec":{"installPlanApproval":"Manual"}}'

# Trigger upgrade (if new version available in channel)
# For demo, just verify manual approval mode
oc get subscription cert-manager -n demo-olm -o yaml | grep installPlanApproval
```

5. **Cleanup**:

```bash
oc delete certificate my-cert -n demo-olm
oc delete issuer selfsigned-issuer -n demo-olm
oc delete subscription cert-manager -n demo-olm
CSV_NAME=$(oc get csv -n demo-olm -o jsonpath='{.items[0].metadata.name}')
oc delete csv ${CSV_NAME} -n demo-olm
oc delete project demo-olm
```

## Quiz (5 Questions)

1. **Q**: What is the difference between Subscription and CSV?  
   **A**: Subscription declares intent to install Operator; CSV is the deployed Operator version.

2. **Q**: What does OperatorGroup do?  
   **A**: Defines which namespaces the Operator watches (AllNamespaces, SingleNamespace, etc.).

3. **Q**: How do you enable manual approval for Operator upgrades?  
   **A**: Set `installPlanApproval: Manual` in Subscription spec.

4. **Q**: What happens if you delete a Subscription without deleting CRs?  
   **A**: CRs remain but are no longer managed; may cause orphaned resources.

5. **Q**: How do you troubleshoot a stuck CSV?  
   **A**: Check `oc describe csv <name>` for errors; review InstallPlan and Operator pod logs.

## Common Mistakes

- **Missing OperatorGroup**: Namespace-scoped Operators require OperatorGroup; install fails silently.
- **Automatic upgrades in prod**: Use `Manual` approval to control upgrade timing.
- **Deleting Operator before CRs**: CRs become orphaned; Operator finalizers may block deletion.
- **Wrong channel**: Subscription channel mismatch prevents upgrades; verify with `oc describe packagemanifest`.
- **Not checking CSV status**: Installing pod != Operator ready; always verify CSV phase is "Succeeded".

## Troubleshooting

See [Triage Matrix: OLM Issues](../troubleshooting/triage-matrix.md#olm)

**Symptom**: CSV stuck in "Installing" phase  
**Triage**: `oc describe csv <name> -n <ns>` shows permission errors or missing dependencies  
**Fix**: Grant required RBAC or install dependency Operators  
**Prevent**: Review Operator documentation for prerequisites before installing

**Symptom**: CR not reconciling (stuck in "Unknown" state)  
**Triage**: `oc logs <operator-pod> -n <ns>` shows reconcile errors  
**Fix**: Check CR spec matches CRD schema; fix validation errors  
**Prevent**: Use `oc explain <crd>` to understand required/optional fields

**Symptom**: InstallPlan stuck "Requires Approval" with automatic approval  
**Triage**: `oc get installplan -n <ns> -o yaml` shows conflicts or errors  
**Fix**: Manually approve or delete/recreate Subscription  
**Prevent**: Test Operator installs in dev before prod
